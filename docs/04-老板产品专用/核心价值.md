# 核心价值

> 面向：老板、投资人、决策层

---

## 我们解决什么问题

| 痛点 | 本系统做法 |
|:---|:---|
| 平台、商家、买家各用各的系统，数据不通 | **一套 API** 服务三端，订单与库存实时一致 |
| 多店铺难以监管 | **Tenant 租户模型**，平台可看全局，商家只见本店 |
| 促销规则复杂、审核散乱 | **统一促销引擎** + **审核工作台** |
| 客服与投诉脱节 | **会话 + 投诉工单** 打通，平台可介入 |
| 国补等政策类业务难落地 | 独立 **国补模块**（政策、备案、SN/IMEI、上报） |
| 运营不知道谁该干什么 | **9 类 RBAC 角色** + 动态菜单 |
| 活动标签难管控 | **标签系统**：平台定义、商家参与、商品最多 3 标签 |

---

## 商业价值

1. **缩短上线周期**：商城 + 商家 + 平台一次交付，无需重复集成  
2. **降低运营成本**：统一审核、统一通知，减少人工盯盘  
3. **提升买家体验**：移动端商城、积分会员、多促销形态  
4. **数据驱动决策**：销售/商品/客户/财务报表内置  
5. **可扩展**：模块化 Django app，可按业务增量启用（国补、标签、评分…）

---

## 与「只做商城」或「只做 ERP」的差异

- 不是单一 B2C 网站：含 **商家自治** 与 **平台治理**  
- 不是传统 ERP：面向 **线上交易 + 营销 + 客服** 场景  
- 员工与买家账号分离，满足 **内控与审计** 要求

## 当前版本能力边界（v1.0.0）

**已具备**：双端 JWT、RBAC、商品订单促销、积分会员、客服投诉、商户入驻、WebSocket 通知、统一审核、国补/标签/店铺评分/注销等。

**规划中/待加强**（见 Baseline §9）：Docker 一键化、按钮级权限、Celery 异步短信、更完整自动化测试覆盖。
