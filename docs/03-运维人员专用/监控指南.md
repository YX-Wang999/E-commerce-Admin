# 监控指南

> 面向：运维工程师  
> 说明：项目当前以 **日志 + 系统指标** 为主，未内置 APM；可按本节接入外部监控。

---

## 1. 监控对象

| 对象 | 指标 |
|:---|:---|
| Daphne 进程 | 存活、CPU、内存、重启次数 |
| Nginx | 5xx 率、响应时间、连接数 |
| 数据库 | 连接数、慢查询、磁盘 |
| Redis | 内存、连接（若启用 Channels） |
| 磁盘 | `media/` 增长、日志轮转 |

---

## 2. 日志位置

### 2.1 后端（systemd）

```bash
journalctl -u ecommerce-backend -f
journalctl -u ecommerce-backend --since "1 hour ago"
```

Django `LOGGING` 配置见 `adminAPI/config/settings.py`（开发默认控制台；生产建议 file handler）。

### 2.2 Nginx

```bash
docker exec <nginx容器> tail -f /var/log/nginx/access.log
docker exec <nginx容器> tail -f /var/log/nginx/error.log
```

### 2.3 应用层关键日志

| 模块 | 关注内容 |
|:---|:---|
| `notification` | WS 推送失败 |
| `orders` | 支付/取消异常 |
| `customers.sms_service` | 短信发送失败 |
| `audit` | 敏感操作（数据库 `audit_operation_log`） |

---

## 3. 健康检查

| 检查项 | 方法 |
|:---|:---|
| API 存活 | `GET /api/system/settings/public/`（需 Token）或专用 health 路由 |
| WebSocket | `wscat -c "ws://host/ws/notify/?token=..."` |
| 数据库 | `python manage.py check --database default` |

建议 Nginx 或负载均衡配置 HTTP 探活（间隔 30s）。

---

## 4. 告警建议

| 级别 | 条件 | 动作 |
|:---|:---|:---|
| P1 | 后端进程退出 / 502 持续 5min | 重启 + 通知值班 |
| P2 | 5xx 率 > 5% | 查 journal + Nginx error |
| P3 | 磁盘 > 85% | 清理 media / 日志 |
| P3 | 短信 API 连续失败 | 检查阿里云 AK 与模板 |

---

## 5. 性能基线（参考）

| 接口 | 预期 |
|:---|:---|
| 商品列表 | < 500ms（P95，无 CDN） |
| 下单 | < 1s（含库存扣减） |
| 报表 | 可能较慢，建议缓存或异步 |

生产环境使用 MySQL + Redis Channel Layer 可显著提升并发与 WS 稳定性。

---

## 6. 审计与合规

- 后台操作：`GET /api/audit/logs/`（需权限）
- 保留策略：建议操作日志 ≥ 180 天（按企业制度配置归档）
