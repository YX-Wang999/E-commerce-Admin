# 部署手册

> 面向：运维工程师  
> 完整脚本与配置模板：[deploy/README.md](../../deploy/README.md)

---

## 1. 服务器要求

| 项 | 最低建议 |
|:---|:---|
| CPU | 2 核 |
| 内存 | 4 GB（含 Nginx 容器 + Daphne） |
| 磁盘 | 40 GB+（含 media 与日志） |
| OS | Linux（Ubuntu 22.04+ 推荐） |
| 网络 | 443 由 Cloudflare/Nginx 终结 HTTPS |

---

## 2. 架构组件

| 组件 | 职责 |
|:---|:---|
| Cloudflare 隧道 / CDN | 公网 HTTPS |
| Nginx 容器 | 静态三端 + 反代 API/WS |
| Daphne (systemd) | Django ASGI + WebSocket |
| Redis | Channels 层（生产推荐） |
| MySQL / SQLite | 数据库（生产用 MySQL） |

---

## 3. 目录规划

```
/var/www/admin/
├── adminDist/          # 平台静态
├── sellerDist/         # 商家静态
├── customerDist/       # 商城静态
├── backend/            # Django 项目 + venv
│   ├── .env
│   ├── db.sqlite3 或 MySQL
│   └── media/
└── deploy/             # 发布脚本
```

Nginx 配置挂载示例：宿主机 `/opt/config/nginx/conf.d/` → 容器 `/etc/nginx/conf.d/`

---

## 4. 首次部署步骤

### 4.1 本地构建

```bash
cp deploy/env/frontend-build.env.example deploy/env/frontend-build.env
# 填写三端 https 公网域名
bash deploy/scripts/build-release.sh
```

### 4.2 上传

```bash
scp deploy/release/*.tar.gz root@your-server:/var/www/admin/
scp -r deploy root@your-server:/var/www/admin/   # 若未上传 deploy.tar.gz
```

发布包含 `deploy.tar.gz`（cron 与部署脚本）；一键部署时会自动解压到 `/var/www/admin/deploy/`。

### 4.3 服务器初始化

```bash
# Nginx 站点配置
cp /var/www/admin/deploy/nginx/0*-ecommerce-*.conf /opt/config/nginx/conf.d/

# 后端环境
cp /var/www/admin/deploy/env/backend.env.example /var/www/admin/backend/.env
vi /var/www/admin/backend/.env

# 一键部署
cd /var/www/admin && bash deploy/scripts/server-deploy-all.sh

# 重载 Nginx
docker exec <nginx容器> nginx -t && docker exec <nginx容器> nginx -s reload
```

### 4.4 数据库

脚本会自动 `migrate` 与 `sync_menus`。首次可选手动：

```bash
cd /var/www/admin/backend && source venv/bin/activate
python manage.py init_data   # 仅首次或重置演示数据
systemctl restart ecommerce-backend
```

## 5. 后续更新（标准流程）

> 服务器示例：`121.196.192.200`，SSH 端口 `2005`，部署目录 `/var/www/admin/`。  
> 按实际环境替换 IP、端口与容器名。

### 5.1 本地构建（不占服务器 CPU）

**Windows（推荐）：**

```powershell
cd "C:\Users\007\Desktop\E-commerce Admin"

# 首次构建前配置域名（仅需一次）
copy deploy\env\frontend-build.env.example deploy\env\frontend-build.env
# 编辑 frontend-build.env，填入三端 https 公网域名

powershell -ExecutionPolicy Bypass -File deploy\scripts\build-release.ps1
```

**Linux / macOS：**

```bash
cd /path/to/E-commerce-Admin
cp deploy/env/frontend-build.env.example deploy/env/frontend-build.env
bash deploy/scripts/build-release.sh
```

**产物**（均在 `deploy/release/`）：

| 文件 | 说明 |
|:---|:---|
| `adminDist.tar.gz` | 平台后台静态 |
| `sellerDist.tar.gz` | 商户后台静态 |
| `customerDist.tar.gz` | 商城前台静态 |
| `backend.tar.gz` | Django 后端代码（不含 venv / db / media） |
| `deploy.tar.gz` | 部署脚本、cron、nginx 模板 |

---

### 5.2 上传到服务器

**全量上传（推荐）：**

```bash
scp -P 2005 deploy/release/*.tar.gz root@121.196.192.200:/var/www/admin/
```

**仅后端：**

```bash
scp -P 2005 deploy/release/backend.tar.gz root@121.196.192.200:/var/www/admin/
```

**仅前端（三端）：**

```bash
scp -P 2005 deploy/release/adminDist.tar.gz deploy/release/sellerDist.tar.gz deploy/release/customerDist.tar.gz root@121.196.192.200:/var/www/admin/
```

**仅部署脚本 / cron（无代码变更时）：**

```bash
scp -P 2005 deploy/release/deploy.tar.gz root@121.196.192.200:/var/www/admin/
# 或首次 / 大改脚本时：
scp -P 2005 -r deploy root@121.196.192.200:/var/www/admin/
```

> 注意：`build-release` 在**本地**执行，不要在服务器上跑 `build-release.sh`（服务器无 Node 构建环境）。

---

### 5.3 服务器部署命令

**一键全量（前端 + 后端 + 脚本）：**

```bash
ssh -p 2005 root@121.196.192.200
cd /var/www/admin
tar -xzf deploy.tar.gz          # 若本次上传了 deploy.tar.gz
bash deploy/scripts/server-deploy-all.sh
docker exec nginx nginx -t && docker exec nginx nginx -s reload
```

**只更新前端：**

```bash
cd /var/www/admin
bash deploy/scripts/server-deploy-frontends.sh
docker exec nginx nginx -s reload
```

**只更新后端：**

```bash
cd /var/www/admin
tar -xzf deploy.tar.gz          # 若需同步最新 deploy 脚本
bash deploy/scripts/server-install-backend.sh /var/www/admin/backend.tar.gz
```

`server-install-backend.sh` 会自动：`pip install` → `migrate` → `collectstatic` → `sync_menus` → 安装 cron（若存在）→ 重启 `ecommerce-backend`。

---

### 5.4 后端维护命令

```bash
cd /var/www/admin/backend
source venv/bin/activate

# 迁移（脚本已执行，手动补跑时用）
python manage.py migrate --noinput

# 同步平台侧栏菜单（RBAC 导航变更后必跑）
python manage.py sync_menus

# 演示数据（仅首次部署或需要重置演示账号时）
python manage.py init_data

# 确认新接口已加载（例：确认收货）
python manage.py shell -c "from django.urls import reverse; print(reverse('order-confirm-receipt', args=[1]))"

systemctl restart ecommerce-backend
systemctl status ecommerce-backend
journalctl -u ecommerce-backend -f
```

| 命令 | 何时执行 |
|:---|:---|
| `migrate` | 后端有模型/迁移变更 |
| `sync_menus` | 平台菜单/权限矩阵变更；侧栏缺项时 |
| `init_data` | **首次**上线或重置演示账号；**日常更新不要跑** |
| `restart ecommerce-backend` | 每次后端代码或 `.env` 变更后 |

---

### 5.5 更新场景速查

| 变更内容 | 本地构建 | 上传 | 服务器执行 |
|:---|:---|:---|:---|
| 仅商城 UI | `build-release.ps1` | `customerDist.tar.gz` | `server-deploy-frontends.sh` + reload nginx |
| 仅平台 UI | 同上 | `adminDist.tar.gz` | 同上 |
| 仅商户 UI | 同上 | `sellerDist.tar.gz` | 同上 |
| 三端 UI | 同上 | 三个 `*Dist.tar.gz` | 同上 |
| 仅后端 API | 同上 | `backend.tar.gz` | `server-install-backend.sh` |
| 后端 + 三端 | 同上 | 全部 `*.tar.gz` | `server-deploy-all.sh` |
| 仅 cron/脚本 | 可不构建 | `deploy.tar.gz` | `tar -xzf deploy.tar.gz` + 手动安装 cron |

**功能涉及前后端联动时**（如确认收货、订单红点、取消通知），必须 **backend + customerDist**（及 adminDist / sellerDist 若相关）一并更新并重启后端。

---

### 5.6 注意事项

| 项 | 说明 |
|:---|:---|
| **端口** | 电商 Daphne 默认 **8002**（`backend/.env` 中 `BACKEND_PORT`）。8000/8001 可留给博客等；改端口后执行 `deploy/scripts/sync-backend-port.sh` |
| **容器网络** | Nginx 在 bridge 容器、Daphne 在宿主机时，`127.0.0.1:8002` 在容器内指向自身；需改为 `host.docker.internal:8002` 或宿主机网关 IP |
| **HTTPS / .env** | 浏览器走 https，CORS / CSRF / `frontend-build.env` 域名一律用 `https://`；Nginx 源站只监听 80 |
| **静态目录** | 确保 `/var/www/admin/*Dist` 已挂载进 Nginx 容器 |
| **init_data** | 会重置/补演示数据，**生产日常更新勿执行** |
| **迁移冲突** | 若 `migrate` 报 `Conflicting migrations`，需部署含 `0011_merge_*` 的最新 `backend.tar.gz` 后再 `migrate` |

## 6. 常用运维命令

```bash
# 服务状态
systemctl status ecommerce-backend

# 重启后端
systemctl restart ecommerce-backend

# 查看日志（按实际配置）
journalctl -u ecommerce-backend -f

# Django 管理
cd /var/www/admin/backend && source venv/bin/activate
python manage.py migrate
python manage.py sync_menus
python manage.py collectstatic --noinput  # 若使用 static
```

## 6.1 定时任务（cron）

后端有两个需定时执行的命令，模板见 `deploy/cron/ecommerce-backend.crontab`。

| 任务 | 命令 | 建议频率 | 说明 |
|:---|:---|:---|:---|
| 支付超时取消 | `cancel_timeout_orders` | 每 5 分钟 | 待支付订单超过 `expires_at` 自动取消 |
| 自动确认收货 | `auto_confirm_receipt` | 每天 02:30 | 已发货满 15 天未签收则自动完成 |

**安装步骤（Ubuntu / Debian）：**

```bash
sudo mkdir -p /var/log/ecommerce
sudo chmod +x /var/www/admin/deploy/scripts/run-scheduled-tasks.sh
sudo install -m 644 /var/www/admin/deploy/cron/ecommerce-backend.crontab /etc/cron.d/ecommerce-backend
```

**手动试跑：**

```bash
/var/www/admin/deploy/scripts/run-scheduled-tasks.sh cancel-timeout
/var/www/admin/deploy/scripts/run-scheduled-tasks.sh auto-confirm-receipt
tail -f /var/log/ecommerce/auto-confirm-receipt-$(date +%Y%m%d).log
```

日志目录：`/var/log/ecommerce/`（按任务名 + 日期分文件）。

## 7. 故障排查

| 现象 | 排查 |
|:---|:---|
| 502 Bad Gateway | Daphne 是否监听；Nginx upstream 端口（默认 8002） |
| WebSocket 失败 | Nginx 是否配置 `/ws` 升级；是否用 Daphne；**Nginx 在 Docker 内时** `.env` 设 `BACKEND_UPSTREAM_HOST=host.docker.internal` 后跑 `sync-backend-port.sh` |
| API 频繁 timeout | 检查 upstream 是否可达；`curl http://127.0.0.1:8002/api/` vs 容器内 `curl http://host.docker.internal:8002/api/` |
| 静态 404 | Dist 目录是否解压；server_name 是否匹配 |
| CORS 错误 | backend `.env` 中 CORS/CSRF 是否为 https 域名 |
| 登录 500 | migrate 是否完整；查看 journalctl |
| 菜单缺失 | `python manage.py sync_menus` |
| 平台收不到取消订单通知 | 需部署**最新后端**（`notification/services.py`）；重启 `ecommerce-backend` |
| 商城无「取消/支付/投诉」按钮 | 重新 `build-release` 并部署 **customerDist**；确认订单未超时 |
| 确认收货 404 | 后端未更新或未重启：检查 `grep confirm_receipt backend/orders/views.py`，执行 `migrate` 后 `systemctl restart ecommerce-backend` |
| 侧栏订单红点不更新 | 重新构建部署 **adminDist**；确认 `/ws/notify/` 返回 101 |

**功能更新后必须同时：**

1. 后端：`systemctl restart ecommerce-backend`
2. 三端前端：执行 `build-release` → 部署 `adminDist` / `sellerDist` / `customerDist`
3. Nginx：`nginx -s reload`（若仅更新静态包可跳过）
