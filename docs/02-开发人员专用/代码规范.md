# 代码规范

> 面向：全体开发人员  
> 原则：与现有代码风格保持一致，见 [架构设计](架构设计.md)

---

## 1. 仓库与目录

| 路径 | 约定 |
|:---|:---|
| `adminAPI/<app>/` | Django app：models、views、urls、serializers、services |
| `admin/src/views/<module>/` | 平台页面，与 RBAC 菜单 path 对应 |
| `customer/src/views/` | 商城页面，按业务分子目录 |
| `seller/src/views/` | 商家页面 |
| `shared/` | 三端共用，禁止引入端特有 UI 库 |

---

## 2. 命名规范

### 2.1 Python（后端）

| 类型 | 规范 | 示例 |
|:---|:---|:---|
| 模块/包 | snake_case | `notification/services.py` |
| 类 | PascalCase | `NotifyConsumer`, `OrderViewSet` |
| 函数/方法 | snake_case | `notify_pending_shipment` |
| 常量 | UPPER_SNAKE | `LOW_STOCK_THRESHOLD` |
| URL name | kebab-case | `customer-notifications-unread` |

### 2.2 JavaScript / Vue（前端）

| 类型 | 规范 | 示例 |
|:---|:---|:---|
| 组件文件 | PascalCase | `NotificationBell.vue` |
| composable | camelCase + use 前缀 | `useHotReload.js` |
| Pinia store | camelCase 文件名 | `notification.js` → `useNotificationStore` |
| API 模块 | 小写业务名 | `api/order.js` |
| i18n key | 点分路径 | `layout.siteTitle` |

---

## 3. API 设计约定

1. **统一响应**：使用 `common.response.success_response` / `error_response`
2. **REST 资源**：ViewSet 标准 CRUD；非 CRUD 用 `@action`
3. **权限**：View 级 `permission_classes`；敏感操作写 `services.py`
4. **通知**：业务侧调用 `notification.services.notify()`，禁止散落 WS 推送
5. **审核**：走 `approval.services`，注册 handler

---

## 4. 前端约定

1. **请求**：统一 `utils/request.js` 拦截器处理 Token 与 `code`
2. **状态**：跨页面共享用 Pinia；页面局部用 `ref`/`computed`
3. **实时**：WebSocket 用 `@shared/composables/useNotifyWebSocketCore.js`
4. **轮询兜底**：WS 断开时 `createBadgePolling`，间隔 30s
5. **i18n**：用户可见文案进 `i18n/domains/`，禁止硬编码中文（除注释）
6. **共享组件**：放 `shared/components/`，端内组件放 `components/`

---

## 5. Git 提交规范

推荐格式：

```
<type>: <简短说明>

<可选正文>
```

| type | 含义 |
|:---|:---|
| feat | 新功能 |
| fix | 修复 |
| docs | 文档 |
| refactor | 重构 |
| test | 测试 |
| chore | 构建/工具 |

示例：

```
feat: 商城导航栏 WebSocket 热加载与红点轮询兜底

fix: 商品标签批量保存最多 3 个
```

---

## 6. 代码审查要点

- [ ] API 是否遵循统一 `{ code, data, message }`
- [ ] 商城接口是否校验 `Customer` 身份
- [ ] 商家数据是否按 `tenant` 隔离
- [ ] 迁移文件是否可逆、是否含数据迁移说明
- [ ] 前端是否处理 loading / 空态 / 错误提示
- [ ] 是否引入不必要的依赖或重复逻辑
- [ ] 敏感信息是否写入 `.env`（勿提交 Git）

---

## 7. 测试要求

| 层级 | 位置 | 命令 |
|:---|:---|:---|
| 后端 API | `adminAPI/*/tests.py` | `python manage.py test` |
| 前端单测 | `customer/src/__tests__/` | `npm run test` |
| E2E | `e2e/*.spec.js` | `npx playwright test` |

新功能优先覆盖主流程；纯 UI 微调可不强制单测。
