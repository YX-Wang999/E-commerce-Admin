## 2. 核心架构原则

### 2.1 双身份体系

| 身份 | 模型 | 认证 | 使用端 |
|:---|:---|:---|:---|
| 后台员工 | `accounts.User` | SimpleJWT (`user_id`) | admin、seller |
| 商城用户 | `customers.Customer` | CustomerJWT (`customer_id`) | customer |

二者 **数据表分离**，API 与权限中间件分别处理。

### 2.2 多租户（商家）

- `tenants.Tenant` 表示店铺
- 商品、订单、购物车等带 `tenant_id` 隔离
- 商家员工通过 `TenantStaff` 绑定 User ↔ Tenant

### 2.3 统一 API 响应

```json
{ "code": 0, "data": {}, "message": "success" }
```

常见业务码：`0` 成功、`1001` 首次改密、`40100` Token 无效、`40300` 无权限、`50000` 服务器错误。

## 3. 后端模块划分（adminAPI）

| App | 职责 |
|:---|:---|
| accounts / rbac | 员工、部门、角色、菜单、权限 |
| customers | 商城注册登录、短信、Customer CRUD |
| products | 类目、品牌、商品、库存日志 |
| orders | 订单、售后、取消日志 |
| cart / addresses | 购物车、收货地址 |
| promotion | 秒杀、拼团、优惠券、超级折扣 |
| points / membership | 积分、会员等级 |
| tenants | 商户、员工、申诉、变更审核 |
| chat / complaints | 客服会话、投诉工单 |
| notification | 站内通知 + WebSocket 推送 |
| approval | 统一审核工作台 |
| tag_system | 促销标签 |
| subsidy | 国补政策与订单 |
| shop_closure / shop_rating | 店铺注销、评分 |
| reports | 报表聚合（无独立 Model） |
| system / audit | 系统配置、操作日志 |

路由入口：`adminAPI/config/urls.py`

## 4. 实时通知架构

```
业务事件 (订单/审核/购物车...)
        │
        ▼
notification.services.notify()
        │
        ▼
tenants.notify.push_*_notify()
        │
        ▼
Channels group (customer_notify_{id} / seller_notify_{id} / staff_notify_{id})
        │
        ▼
notification.consumers.NotifyConsumer
        │
        ▼
前端 useNotifyWebSocket → Pinia Store → 导航红点 / 标题提示
        │
        ▼ (WS 断开)
shared/useBadgePolling 30s 轮询兜底
```

WebSocket 路径：`/ws/notify/?token=...`（商家附加 `tenant_code`）

## 6. 核心业务流程

### 6.1 下单流程

```
选商品 → 加购物车 → 结算 → 创建 Order(pending)
  → 支付(paid) → notify_pending_shipment → 商家/平台通知
  → 发货(shipped) → 物流 → 完成(completed)
```

### 6.2 统一审核流程

```
业务提交 (标签参与/店铺注销/促销…)
  → approval.services 创建 Approval
  → notification 通知审核人
  → 平台 /approvals 工作台处理
  → handler 回调业务模块
```

## 7. 安全与认证

| 能力 | 实现 |
|:---|:---|
| 后台登录滑块 | `accounts.slider_captcha` + 信任分级 |
| JWT 刷新 | `/api/auth/refresh/`、`/api/customers/auth/refresh/` |
| RBAC | 角色 → 权限 + 动态菜单 |
| CORS | `django-cors-headers`，生产需配置域名 |
| 审计 | `audit.OperationLog` 记录关键操作 |
